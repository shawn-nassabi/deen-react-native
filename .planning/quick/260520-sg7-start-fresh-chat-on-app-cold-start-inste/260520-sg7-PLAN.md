<objective>
On a cold start of the app (process launch, OS-killed, or user-killed), the chat screen must open with a brand-new session (fresh `sessionId`, empty messages list) instead of auto-restoring the previously-active session from AsyncStorage. Warm behavior (tab-switching within the same app process) must continue restoring the in-progress conversation. All historical chats (in the drawer and in AsyncStorage) must remain intact and accessible.

Purpose: A returning user opening the app should land in a clean chat ready for a new question, not in the middle of yesterday's conversation. Old chats are still reachable via the history drawer.

Output: A small, focused edit to `app/(tabs)/chat.tsx` that introduces a module-scoped `coldStartHandled` flag and branches the initialization effect to start a fresh session on the first mount per JS runtime.
</objective>

Implement the "fresh session on cold start, restore on warm remount" behavior using a module-level flag.

1. Near the top of `app/(tabs)/chat.tsx` (just below the existing imports, above the `INPUT_CONTAINER_HEIGHT` constant block), add a module-level mutable flag. This survives component unmount/remount within the same JS runtime, but is re-initialized on every fresh runtime (process launch / OS-kill / dev reload):

   ```ts
   // Module-level flag: true once the chat screen has mounted at least once in this JS runtime.
   // Reset to false on every cold start (new process / OS-kill / dev reload), which is exactly
   // when we want to start a fresh chat instead of restoring the previously-active session.
   let coldStartHandled = false;
   ```

2. Add a module-level ref-like guard for the cold-start branch within the initialize effect to keep behavior deterministic across React StrictMode double-invocation in dev. Implement by reading-then-setting the flag synchronously inside the effect (before any `await`) so the second StrictMode invocation falls into the warm branch.

3. Replace the current initialization `useEffect` (currently lines ~201-210) with the branched version:

   ```tsx
   // Initialize session: on cold start, force a fresh session and empty chat.
   // On warm remounts (tab switches within the same JS runtime), restore the active session.
   useEffect(() => {
     const isColdStart = !coldStartHandled;
     coldStartHandled = true;

     const initialize = async () => {
       console.log(
         isColdStart
           ? "🚀 Chat screen cold-start — starting fresh session"
           : "🚀 Chat screen warm-mount — restoring active session"
       );
       // Always safe to run; only deletes sessions older than CHAT_EXPIRY_SECONDS.
       await purgeExpiredSessions();

       if (isColdStart) {
         // Fresh session id; also overwrites the persisted "active session" pointer
         // so any future code that reads it sees the new one. Old per-session message
         // blobs under deen:msgs:<oldId>:v1 are intentionally left untouched — history
         // remains available via the ChatHistoryDrawer (server-backed).
         const freshId = await startNewConversation();
         setSessionId(freshId);
         setMessages([]);
         setShowSuggestions(true);
       } else {
         const sid = await getOrCreateSessionId();
         setSessionId(sid);
       }
     };

     initialize();
   }, []);
   ```

4. Update the existing "load messages when session id changes" effect (currently lines ~228-239) to skip the load on the cold-start branch's session. The cleanest way: gate the load on the session NOT being the one we just freshly created with no messages. Implement by tracking with a ref:

   ```tsx
   // At the top of the component, alongside the other refs:
   const skipNextMessageLoadRef = useRef(false);
   ```

   In the cold-start branch above, set the ref BEFORE setting state:

   ```tsx
   if (isColdStart) {
     skipNextMessageLoadRef.current = true;
     const freshId = await startNewConversation();
     setSessionId(freshId);
     setMessages([]);
     setShowSuggestions(true);
   } else { ... }
   ```

   And in the existing message-load effect, consume the ref:

   ```tsx
   useEffect(() => {
     if (!sessionId) return;
     if (skipNextMessageLoadRef.current) {
       skipNextMessageLoadRef.current = false;
       return;
     }
     const loadInitialMessages = async () => {
       const initial = await loadMessages(sessionId);
       if (initial.length > 0) {
         console.log(`💾 Loaded ${initial.length} message(s) from storage`);
       }
       setMessages(initial);
     };
     loadInitialMessages();
   }, [sessionId]);
   ```

   Why a ref and not a state flag: state changes would trigger an extra render and could race with `setSessionId`. The ref is read synchronously inside the effect, exactly once per cold-start sessionId.

   - The history drawer (`ChatHistoryDrawer.tsx`) — entirely unchanged. It fetches saved chats from the backend, so all historical chats remain visible.
   - `utils/chatStorage.ts`, `utils/api.ts`, `utils/constants.ts` — no changes.

Code style: 2-space indent, double quotes, `@/` import paths only (no new imports needed for this change; `useRef` is already imported). No `console.error` for the cold-start branch — `console.log` only, matching the rest of the file's logging style.
