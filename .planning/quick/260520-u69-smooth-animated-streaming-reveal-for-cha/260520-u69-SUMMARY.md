# Quick 260520-u69: Smooth Animated Streaming Reveal Summary

Replaced the chat screen's per-chunk "2-line jump" rendering with a JS-timer typewriter so streaming responses reveal at a steady character cadence; backend, storage, and markdown rendering are untouched.

## What Changed

### `hooks/useStreamingText.ts` (new, 91 lines)

Single exported hook:

```typescript
export function useStreamingText(
  target: string,
  isActive: boolean,
  opts?: { charsPerTick?: number; intervalMs?: number; maxLagBeforeBoost?: number }
): string
```

- Holds a `displayed` string (state) that advances toward `target` on a `setInterval(tick, intervalMs)` loop.
- `targetRef` + `activeRef` are kept in sync via a separate effect so the tick body always reads the latest values without tearing down the interval on every render.
- Step size is `charsPerTick` (default 2) per tick; when the remaining tail exceeds `maxLagBeforeBoost` (default 120), step grows to `ceil(remaining / 20)` so the reveal accelerates to stay close to the backend.
- Interval is cleared in two places: (a) inside the tick once `displayed === target && !isActive`, (b) the effect cleanup on unmount / dep change.
- `displayed` is reset to `""` whenever `target` shrinks (signals a new stream session) so leftover characters from the previous response never bleed in.

### `app/(tabs)/chat.tsx` (modified, +27 / -9 lines)

- New `streamingTarget` state plus `const displayedStreamingText = useStreamingText(streamingTarget, isStreaming)`.
- `handleSendMessage` clears `streamingTarget` at start, feeds `setStreamingTarget(fullMessage)` in `onChunk` (replacing the per-chunk write into `messages[]`), and clears `streamingTarget` in the `onError` and outer `catch` branches. `onComplete` is unchanged — it still writes the final text + references into `messages[]` and flips `isStreaming` false; the hook then keeps ticking until caught up and stops on its own.
- `renderMessage` substitutes `{ ...item, text: displayedStreamingText }` only for the active streaming bot row (`isStreaming && sender === "bot" && index === messages.length - 1`); user messages, history, and older bot messages are untouched. Added `displayedStreamingText` to the `useCallback` deps so the FlatList re-renders the streaming row on each typewriter tick.

## Tuning Knobs (defaults)

| Knob | Default | Notes |
|------|---------|-------|
| `charsPerTick` | `2` | Base step; bump to 3–4 if it feels too slow on long responses |
| `intervalMs` | `16` | ~60 fps; raising to 24–32 reduces work if older devices struggle |
| `maxLagBeforeBoost` | `120` | Tail length (chars) past which step grows adaptively |

These are passed via the `opts` param to `useStreamingText`; chat.tsx currently uses the defaults. The plan-level human-verify step (Task 3) is the place to re-tune if the feel is off.

## Edge Cases Covered

- **History load** (`handleSelectChat`): `isStreaming` stays false, so `displayedStreamingText` is never substituted — historical messages render instantly.
- **User echo**: `isThisStreaming` requires `sender === "bot"`, so user messages bypass the smoother.
- **Past bot messages**: only `index === messages.length - 1` gets the substitution; older completed responses render from `messages[].text` directly.
- **References / copy button / language switching**: `onComplete` still writes the canonical final text + references into `messages[]`, so the copy chip copies the full final response (not the partial reveal) and references render exactly as before.
- **Errors / aborts**: `onError` and outer `catch` set `setStreamingTarget("")` and `setIsStreaming(false)`; the hook clears its interval automatically once it sees `displayed.length >= target.length && !isActive`.
- **Fast backend**: adaptive `step` keeps reveal within ~120 chars of the buffered tail at all times.
- **New stream while previous still revealing**: `setStreamingTarget("")` at the start of `handleSendMessage` shrinks `target`, which triggers the hook's "reset displayed to ''" path, preventing bleed-through.
- **Unmount mid-stream** (tab switch, navigation away): effect cleanup clears the interval.
